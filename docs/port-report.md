# Port report: erdtree on Opus 2 and the eight Opus presets

2 November 2026. What was found, what was done, what was tested and how, and what is still open. "Tested" here
always means on a PC (host builds, and GDB's Blackfin instruction simulator). Nothing in this report was run on an
OP-1 unless it says so.

## 1. The two environments

**erdtree (the source).** A synth engine for op1r and the Hundekraft Workshop: one C file (`src/erdtree.c`)
against the kennel/op1r engine API, with its tables generated by Python, an OS screen (`erdscreen.c` over
`erdtree.svg`), and eight presets written by `presets.py` as OP-1 patch files of `"type": "erdtree"`. Each voice
renders a choir, strings and a brass horn (Brassophone's) and mixes them under four controls: choir, strings, space,
brass. Details: `shared/design-notes/engine.md`.

**Opus 2 (the target).** LizardMan's plugin manager for firmware 246 (https://github.com/LizardMan245/opus, plugin
kit for beta 3.2, commit `d7f28b0`). A plugin is an `.opmod` built by `plugin_tool.py` from a folder with a
`manifest.txt` and C; an engine registers a `struct opus_engine` from `opl_init` with `opus_engine_add`. What
mattered for the port, all from the kit's `sdk/opus_plugin.h` and `docs/api.md`:

- The engine keeps its own voice state (`voice` bytes, six voices); `render` writes 128 samples at 88.2 kHz; the OS
  does the envelope, the velocity and the mix around it.
- A plugin's CPU is measured every block against its `cpu.txt` figure; 25 % over in 8 of 64 blocks switches its
  voices off (silent) unless developer mode is on.
- Memory: L1 fast memory (`opus_fast`, about 25 KB shared), the audio pool (`opus_alloc_audio`), ordinary memory
  (slow for scattered reads).
- An engine sound is saved as the OS's `iter` with the engine's number in knob 4 and an `"opus"` member naming the
  plugin. The number is "made from the plugin's id and the engine's name"; neither the formula nor the member's layout
  is documented.
- `type` lets sounds of another firmware's engine load as this one. erdtree claims `"erdtree"`, but LizardMan
  reports that Hundekraft presets do not load on Opus (Opus Discord, 1 Nov 2026).

## 2. Porting decisions

- **Same DSP, new wrapper.** The Opus build's `erdtree.c` keeps v0.5's synthesis and wraps it in Opus's engine
  struct: its own 36-byte voice, `init` stores the voice index, the velocity left to the OS. The match test keeps the
  two sample-for-sample (within 3 LSB).
- **0.6.1 for the silence.** 0.6.0 loaded but was silent, most likely switched off by the CPU guard. 0.6.1 copies the
  sine and choir tables into fast memory and the warp table into the audio pool, redraws the page only when the
  knobs or the animation step change (about 10 times a second at most), adds a `screen` setting, a release handler,
  and declares 200,000 cycles.
- **Presets as data.** Each Opus preset is a folder with `sound.json`; `presets.py` checks it and will write its
  `.aif`. Only real controls are used: the four knobs, the OS envelope, octave and one stock effect (spring, delay or
  grid) inside the factory ranges. The LFO is off, because only the tremolo default's values are known to be valid
  and an invalid value makes the OS import the file as a sample.
- **No guessed formats.** The Opus `.aif` files are not written until one real saved erdtree sound shows erdtree's
  number and the `"opus"` member (`OPUS_FORMAT` in `presets.py`).
- **Repository by firmware.** "op1" in the proposed layout became `hundekraft`: both builds run on the same OP-1, so
  the firmware mod is what tells them apart. The separate source zip is unpacked into the tree (the brief asked for
  source, tests and builds in platform folders); the single mixed `erdtree.zip` became one download per firmware.

## 3. The eight presets

Names, values, measurements and how to hear them apart: `docs/preset-guide.md`. Design intent:
`shared/preset-specifications/dark-fantasy-collection.md`.

crown of ash, the hollow belfry, thornwake, vesperglass, the sunken choir, grave of giants, moonless vigil, the
unwritten god.

The hollow belfry is bell-like, not a bell: erdtree has no inharmonic source, so its "bell" is a struck brass and
choir with no sustain whose tone darkens as it decays.

## 4. Resource use

| | Measured how | Result |
|---|---|---|
| CPU, heaviest preset (crown of ash, the unwritten god) | Blackfin simulator, six voices, instructions only | 131,238 to 132,300 cycles a block, 23 % of the block |
| CPU, lightest (vesperglass) | the same | 54,870, 9 % |
| CPU, all levels at zero | the same | 17,904 |
| CPU on the OP-1 | not measured | the simulator does not count memory waits, so the device will be higher |
| Declared figure | `cpu.txt` | 200,000 |
| Memory | build output, `plugin_tool.py show` | 47,664 bytes of code and data, 504 zero fill, voices 6 × 36 bytes, 4 KB fast memory, 33 KB audio pool for the warp table |
| Peak, six voices, random extremes | stress run, 3 seeds × 400,000 blocks | 31,364 of 32,767: no clipping in the engine's sum |

## 6. Still open

1. **Does 0.6.1 make sound on the OP-1?** If not, the mods list row and "audio: worst N" with developer mode on say
   why.
2. **The Opus preset format.** One erdtree sound saved on Opus (its `.aif` from the disk's `synth` folder) gives
   `OPUS_FORMAT`; then `python3 platforms/opus/presets/presets.py aif` and `scripts/build-platform/package.sh opus`.
3. **Preset names over 14 characters.** Opus keeps names up to 23 characters, but the factory presets never go past
   14; four of the eight are longer (the hollow belfry, the sunken choir, grave of giants, the unwritten god). To
   check on the device.
4. **The effects.** What each stock effect parameter does was not measured; tune by ear on the device.
5. **The Hundekraft set's names** (malenia lament, leyndell hall, starscourge, roundtable, golden order) use game
   names. The Opus collection avoids them; the Hundekraft set was left as released.
6. **Before sharing on Opus:** the kit's `docs/sharing.md` checklist and a measured `cpu.txt`.
